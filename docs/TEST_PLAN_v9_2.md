# แผนทดสอบ v9.2 — รันทีละข้อ อย่ารวบ

เปิดกราฟเดิม ช่วงเวลาเดิม (2 ม.ค. 2025 – ปัจจุบัน) แล้วรันตามลำดับนี้
จดแค่ 4 ตัวเลขต่อรอบ: **Net PnL / Max DD / Profit Factor / จำนวนไม้**

ตัวเลข baseline ของ v9 ที่วัดไว้แล้ว:

```
Net PnL  +1,138.09   Max DD 25.06%   PF 1.262   658 records (≈329 ไม้จริง)
```

| รอบ | ตั้งค่า | ต้องการรู้ว่า |
|---|---|---|
| **0** | ปิดการแก้ทั้ง 3 + `limitExpiry = 999` | ได้ตัวเลขเท่า v9 เป๊ะมั้ย — ถ้าไม่เท่า แปลว่าผมพอร์ตโค้ดมาผิด **หยุดแล้วบอกผม** |
| **1** | เปิด `แก้บั๊ก 1` อย่างเดียว + `limitExpiry = 6` | ออเดอร์ค้าง/SL ถูกเขียนทับ ทำเสียหายไปเท่าไร |
| **2** | เปิด `แก้บั๊ก 2` เพิ่ม | SL ที่หายไปตอนแท่งที่ออเดอร์ติด ทำเสียหายเท่าไร — ดูที่ **ขาดทุนเฉลี่ยต่อไม้** ควรลดลงมาต่ำกว่า $12 |
| **3** | เปิด `BE` เพิ่ม (`beBufAtr = 0.1`) | ข้อที่ผมประเมินว่าคุ้มสุด ผมคาด Net PnL ขึ้นไปแถว **$2,500–3,200** |
| **4** | เปิด `noRepaint` เพิ่ม | กำไรมาจาก repaint หรือเปล่า — ถ้าตกแรง แปลว่าของเดิมพึ่ง repaint |
| **5** | Properties: Commission `0.30` cash per contract, Slippage `2` | เหลือกำไรจริงเท่าไรหลังหักต้นทุน |
| **6** | เปิด Use bar magnifier (ถ้าแพ็กเกจมี) | ตัวเลขจริงหลังตัดการเดาลำดับ TP/SL ในแท่งเดียวกันออก |

**รอบ 5 คือรอบตัดสิน** ถ้า PF ตกต่ำกว่า 1.1 ตรงนั้น = ระบบนี้ยังเทรดจริงไม่ได้ ไม่ว่าตัวเลขรอบก่อนหน้าจะสวยแค่ไหน

## หลังจากนั้น — ทดสอบ out-of-sample

ในกลุ่ม `8. Reality check` เปิด `จำกัดช่วงเวลาเทรด` แล้วรัน 2 ช่วงแยกกัน
โดย **ห้ามแตะพารามิเตอร์อื่นเลย**

- ม.ค. 2025 – ธ.ค. 2025 (in-sample — ช่วงที่ค่าถูกจูนมา)
- ม.ค. 2026 – ปัจจุบัน (out-of-sample)

ถ้าช่วงหลังกำไรหายไปเกินครึ่ง = ค่าพารามิเตอร์ถูก curve fit ไม่ใช่ขอบจริง

ดีที่สุดคือลากกราฟย้อนไป **2022–2024** (ปีที่ทองออกข้าง) แล้วรันด้วยค่าเดิม
ถ้ายังไม่ขาดทุนค่อยเริ่มเชื่อ
