# รีวิว XAUUSD SMC Pro v9 — เน้นการใช้งานบน H1

ไฟล์ที่เกี่ยวข้อง
- `src/XAUUSD_SMC_Pro_v9.pine` — โค้ดต้นฉบับตามที่ส่งมา (เก็บไว้เทียบ)
- `src/XAUUSD_SMC_Pro_v9_1_H1.pine` — เวอร์ชันแก้แล้ว

สรุปสั้น: โค้ด **compile ผ่านและทำงานได้** ไม่มี syntax error แต่มีบั๊กเชิงตรรกะ 10 จุด
ที่ทำให้ฟิลเตอร์หลายตัว "มีอยู่แต่ไม่ทำงาน" และมี 3 จุดที่กระทบผลเทรดจริงบน H1 โดยตรง

## A. บั๊กที่กระทบผลเทรดจริง (ควรแก้ก่อน)

### A1. MTF Bias repaint — คอมเมนต์บอกว่าไม่ repaint แต่จริง ๆ repaint

```pine
// ต้นฉบับ
request.security(syminfo.tickerid, _tf, [ta.ema(close, emaFast), ta.ema(close, emaSlow)], lookahead=barmerge.lookahead_off)
```

`lookahead_off` แปลว่า "ไม่แอบดูอนาคต" — **ไม่ได้แปลว่า "ใช้ค่าที่ปิดแล้ว"**
ค่าที่ได้คือค่าของแท่ง HTF ที่ *กำลังก่อตัวอยู่* เช่นบนกราฟ H1 ค่า `bias_d1`
จะเปลี่ยนไปมาได้ตลอดทั้งวัน แล้วพอ replay/รีเฟรชกราฟ ประวัติจะไม่เหมือนเดิม
→ สัญญาณที่เห็นย้อนหลังสวยกว่าที่เกิดจริง

แก้เป็นสูตรมาตรฐาน `lookahead_on` + ดึงค่า `[1]` (แท่ง HTF ที่ปิดแล้วเท่านั้น):

```pine
request.security(syminfo.tickerid, _tf,
     [ta.ema(close, emaFast)[1], ta.ema(close, emaSlow)[1]],
     gaps=barmerge.gaps_off, lookahead=barmerge.lookahead_on)
```

### A2. เล่น H1 แล้วตั้ง "ยืนยันด้วย TF = H1" → ฟิลเตอร์ MTF ไม่ทำงานเลย

ค่า default คือ `mtfConfirm = "H1"` ถ้าเปิดกราฟ H1 อยู่ `confirmBias` จะเท่ากับ
`ema21 > ema50` ของกราฟเองแบบเป๊ะ ๆ ผลคือ:

- `mtfBuyOK` ให้ผลเท่ากับ `trendUp` → ไม่ได้กรองอะไรเพิ่มเลย
- ใน `buyScore` แต้ม `trendUp` กับเงื่อนไข MTF เป็นเรื่องเดียวกัน = **นับคะแนนซ้ำ**

**เล่น H1 ต้องตั้งเป็น H4** (v9.1 เปลี่ยน default เป็น H4 แล้ว และถ้าเลือก TF ที่
เท่ากับ/ต่ำกว่ากราฟ ตารางจะขึ้นเตือน `→ ใช้กราฟ`)

### A3. เพดาน SL บีบ SL ให้แคบกว่าความผันผวนจริง

```pine
slDistBase = math.min(atrVal * slAtrMult, maxSLusd)   // maxSLusd = 12
```

ATR(14) ของทองบน H1 อยู่ราว $5–15 ช่วงข่าวขึ้นไป $20+ เมื่อ `atrVal * 1.2 > 12`
โค้ดจะไม่ข้ามไม้ แต่ **หั่น SL ให้เหลือ 12** แล้วเข้าไม้อยู่ดี
→ ได้ไม้ที่ SL แคบกว่าที่ระบบเองประเมินว่าต้องใช้ = โดนกวาดทิ้งเป็นเรื่องปกติ
และ TP1/TP2 ก็หดตามเพราะคิดจาก `buySLdist` ตัวเดียวกัน

v9.1 เพิ่มสวิตช์ `wideSLskip` (default เปิด): ATR กว้างเกินเพดาน → **ข้ามสัญญาณ**
ไม่ใช่บีบ SL และปรับ default เป็น `slAtrMult 1.5` / `maxSLusd 20` ให้เข้ากับ H1

> หมายเหตุหน่วย: ที่ 0.01 lot (= 1 oz) ราคาขยับ $1 = กำไร/ขาดทุน $1 พอดี
> ดังนั้น `maxSLusd` = ระยะราคาเป็นดอลลาร์ = เงินจริงต่อไม้ ตรงนี้คิดถูกแล้ว

## B. บั๊กที่ทำให้ฟิลเตอร์ "มีแต่ไม่ทำงาน"

### B1. ขอ M15/M30 จากกราฟ H1 = ขอ TF ที่ต่ำกว่ากราฟ

`request.security` ไปยัง TF ที่ต่ำกว่ากราฟ ให้ค่าที่ไม่น่าเชื่อถือ (ได้แค่ค่าสุดท้าย
ของ LTF ในแท่งนั้น) และผลย้อนหลังกับ realtime ไม่ตรงกัน

ผลต่อเนื่อง: `allBull` / `allBear` ต้องการให้ครบทั้ง 5 TF รวม M15/M30 ด้วย
เมื่อ `rtNeedAlign = true` สัญญาณ realtime แทบไม่มีทางเกิดเลย

v9.1 ตัด TF ที่ต่ำกว่ากราฟออกอัตโนมัติ (แสดง `n/a` ในตาราง) และคิด align
เฉพาะ TF ที่ใช้ได้จริง

### B2. RSI OB / OS เป็นค่าตาย

```pine
rsiOK_buy = rsiVal > 35 and rsiVal < rsiOB and rsiVal < noChaseHi   // 70 vs 62
```

`noChaseHi` (62) < `rsiOB` (70) เสมอ → เงื่อนไข `rsiVal < rsiOB` ไม่มีผลใด ๆ
เช่นเดียวกับฝั่ง sell และเลข `35` / `65` เป็น hardcode ที่ไม่ผูกกับ input
แก้เป็น `rsiVal > rsiOS and rsiVal < math.min(rsiOB, noChaseHi)`

### B3. Volume filter พังถ้าฟีดไม่มี volume

โบรก/ฟีด XAUUSD หลายเจ้าไม่มี volume (`na`) ทำให้ `volume > avgVol * 0.7`
เป็น false ตลอด → เสียแต้มฟรี 1 คะแนนทุกแท่ง สัญญาณแทบไม่ผ่าน `minScore`
แก้โดยเพิ่ม `na(volume)` เป็นทางผ่าน

### B4. FVG ถูกวาดแต่ไม่ถูกใช้ตัดสินใจเลย

`bullFVG` / `bearFVG` ไม่ปรากฏใน `buyScore`, `baseBuy` หรือที่ไหนอีกเลย
FVG เป็นแค่กราฟิก — ระบบที่เรียกตัวเองว่า SMC แต่ไม่ใช้ FVG เป็น confluence

ซ้ำร้าย ตรรกะ FVG ทั้งก้อนอยู่ใน `if showFVG` → **ปิดปุ่มแสดงผล = logic หายไปด้วย**

v9.1 แยกส่วนคำนวณออกจากส่วนวาด เก็บโซนไว้ใน UDT และเพิ่ม `useFvgScore`
ให้ +1 คะแนนเมื่อราคาอยู่ในโซน FVG ที่ยังไม่ถูกเติม

### B5. `minScore` 4 แต้ม = ผ่านได้โดยไม่ใช้โครงสร้าง SMC เลย

`trendUp + rsiOK + trigger + volOK` = 4 แต้มพอดี ครบตาม default
แปลว่า BOS / CHoCH / marketBias **ไม่จำเป็นต้องเกิดเลย** ระบบก็ยิงสัญญาณ
ตัวชี้วัดที่เหลือกลายเป็นแค่ EMA + RSI + แท่งเทียน

v9.1 เพิ่ม `reqStruct` (บังคับ `marketBias` ตรงทาง) และดัน default `minScore` เป็น 5
จากคะแนนเต็มใหม่ 8

## C. บั๊กเชิงเทคนิค / เสถียรภาพกราฟ

### C1. โหมด Limit นับผลทั้งที่ออเดอร์อาจไม่เคยติด

ป้ายบอกว่า "วาง Buy Limit ที่ราคาต่ำกว่า close 0.4×ATR" แต่โค้ดวาดเส้น TP/SL
แล้วเริ่มเช็ค `hitTP2` / `hitSL` ทันทีตั้งแต่แท่งที่เกิดสัญญาณ โดยไม่เคยเช็คว่า
ราคาย่อลงมาแตะ `buyEntry` หรือยัง และไม่มีวันหมดอายุของ limit

ผลคือเส้นบนกราฟบอกว่า "ไม้นี้ TP" ทั้งที่ในบัญชีจริงออเดอร์ไม่เคยติด

v9.1 เพิ่มสถานะ `pending → filled → closed/cancelled` + `limitExpiry` (default 6 แท่ง)

### C2. array โตไม่จำกัด + drawing เกินลิมิตถูกลบเงียบ ๆ

- `trades` push เข้าอย่างเดียว ไม่เคยลบ และ loop วนทุกไม้ทุกแท่ง
- 1 ไม้ = 4 เส้น → ประมาณ 125 ไม้ก็ชน `max_lines_count = 500`
  TradingView จะลบเส้นเก่าทิ้งเอง แต่ array ยังถือ id เดิมอยู่ → `line.set_x2` ไม่มีผล
- `bullBoxes` / `bearBoxes` เหมือนกัน โดยเฉพาะถ้าปิด `fvgMitig` (ไม่มีอะไรลบเลย)

v9.1 จำกัดจำนวนที่เก็บ (`maxTradeKeep`, `maxFvgKeep`) และลบ drawing พร้อมกับ
เอาออกจาก array

### C3. swing เก่าค้างถูกใช้เป็น SL

`swH1` / `swL1` เก็บ pivot ล่าสุดโดยไม่มีอายุ ถ้าไม่มี pivot ใหม่หลายสิบแท่ง
`buySwingDist` อาจอ้างอิงจุดที่เกิดเมื่อหลายวันก่อน — v9.1 เพิ่ม `swMaxAge` (60 แท่ง)

นอกจากนี้ต้นฉบับเช็ค `buySwingDist <= maxSLusd` **ก่อน** แล้วค่อยบวกบัฟเฟอร์
`+ atrVal * 0.1` ทีหลังแล้ว cap อีกที → บางกรณี SL จบลงที่เพดานพอดีเป๊ะโดยไม่ตั้งใจ
v9.1 รวมบัฟเฟอร์เข้าไปก่อนเช็ค

### C4. `buyQualOK = buySLdist > 0` เป็นเงื่อนไขที่เป็นจริงเสมอ

ATR > 0 ตลอด เงื่อนไขนี้จึงไม่เคยกรองอะไร (ไม่ได้ทำให้พัง แต่ไม่มีประโยชน์)
v9.1 เพิ่ม `not na(atrVal)` และผูกกับเงื่อนไข SL กว้างเกินตาม A3

### C5. จุดเล็ก ๆ อื่น ๆ

- `mtfSum >= 3` ใช้ตัดสิน "STRONG UP" โดยสมมติว่ามี 5 TF เสมอ — ผิดเมื่อบาง TF ถูกตัด
- `marketBias` เริ่มที่ 0 → break ครั้งแรกของกราฟถูกนับเป็น CHoCH เสมอ (ยอมรับได้ แต่ควรรู้)
- `rtMinScore` (5) > `minScore` (4) → สัญญาณ realtime เข้มกว่า confirmed
  ซึ่งกลับด้านกับคำว่า "early warning" (จงใจกัน spam ก็ได้ แต่ควรรู้ว่าเป็นแบบนี้)
- `diP_`, `diM_` ประกาศแล้วไม่ได้ใช้ (ไม่มีผล)
- ป้ายสัญญาณไม่ได้บอกวิธีจัดการหลัง TP1 ทั้งที่ tooltip เขียนว่า "ปิดครึ่งไม้"
  → v9.1 เติมบรรทัด "โดน TP1 → เลื่อน SL มา BE" ลงในป้าย

## D. สิ่งที่ยัง "ขาด" สำหรับเทรดทองบน H1 จริงจัง

| หัวข้อ | สถานะเดิม | v9.1 |
|---|---|---|
| Session filter (London/NY) | ไม่มี | เพิ่มแล้ว default 08:00–23:00 London |
| ตัวนับผล TP/SL บนกราฟ | ไม่มี | เพิ่มในตาราง (TP2/SL/winrate, TP1, ยกเลิก, รอ) |
| แจ้งเตือนว่าตอนนี้ SL จะกว้างเท่าไร | ไม่มี | เพิ่มแถว "SL ที่จะใช้" |
| กรองข่าวแรง (NFP/CPI/FOMC) | ไม่มี | **ยังไม่มี** — Pine ดึงปฏิทินข่าวไม่ได้ ต้องเลี่ยงเอง |
| จำกัดจำนวนไม้ต่อวัน / daily loss limit | ไม่มี | **ยังไม่มี** — เหมาะไปทำในตัว strategy มากกว่า |
| คิด spread / commission | ไม่มี | **ยังไม่มี** — ทอง spread 20–40 point กินสัดส่วนไม่น้อยเมื่อ SL แคบ |

สองข้อหลังสำคัญ: ถ้าจะรู้ว่าระบบกำไรจริงไหม ต้องทำเป็น `strategy()` แล้วใส่
`commission_type=strategy.commission.cash_per_order` กับ slippage ตามจริง
ตัว `indicator()` นับ TP/SL แบบในตารางนี้เป็นแค่ตัวเลขคร่าว ๆ (ไม่รู้ลำดับ
ภายในแท่งว่า TP หรือ SL มาก่อน — v9.1 นับแบบระวังไว้ก่อนคือให้ SL ชนะ)

## E. ค่าที่แนะนำสำหรับ H1

```
ยืนยันด้วย TF        : H4        ← สำคัญที่สุด (ห้ามใช้ H1)
Min Score            : 5         (จากเต็ม 8)
บังคับโครงสร้าง SMC  : เปิด
SL = ATR ×           : 1.5
SL สูงสุด            : 20
ATR กว้างเกิน → ข้าม : เปิด
TP1 / TP2            : 1.0 / 2.0

ระยะห่างสัญญาณ       : 15 แท่ง   (≈ 15 ชั่วโมง)
```

จำนวนสัญญาณจะลดลงจากเดิมพอสมควร — นั่นคือผลที่ตั้งใจ เพราะเวอร์ชันเดิม
ปล่อยผ่านไม้ที่ไม่มีโครงสร้าง SMC รองรับและไม้ที่ SL ถูกบีบให้แคบเกินจริง

## ภาคผนวก — ตรวจซ้ำรอบที่สอง (พร้อมกับตอน v9.5 ICT)

โค้ดที่ส่งมาตรวจรอบนี้คือไฟล์เดิมเป๊ะ ๆ (`src/XAUUSD_SMC_Pro_v9.pine`)
บั๊ก A1–A3, B1–B5, C1–C5 ข้างบนยังเป็นคำตอบที่ใช้ได้ทั้งหมด ไม่มีอะไรเปลี่ยน
สรุปคือ **ไม่มี syntax error — compile ผ่าน — แต่บั๊กเชิงตรรกะ 3 จุดกระทบเงินจริง**
คือ A1 (MTF repaint), A2 (เลือก TF ยืนยัน = TF ของกราฟ ฟิลเตอร์ตายทั้งอัน),
A3 (เพดาน SL บีบ SL แคบกว่าความผันผวนจริง แล้วยังเข้าไม้อยู่ดี)

สิ่งที่เจอ **เพิ่ม** จากการไล่โค้ดรอบนี้:

### F1. v9.4 LIVE ไม่ได้เอาการแก้ B2 ติดไปด้วย

```pine
// v9.1 แก้ไว้แล้ว
rsiOK_buy = rsiVal > rsiOS and rsiVal < math.min(rsiOB, noChaseHi)

// แต่ v9.4 กลับไปใช้เลขตายตัวเหมือนต้นฉบับ
rsiOK_buy = rsiVal > 35 and rsiVal < rsiOB and rsiVal < noChaseHi
```

ผลคือใน v9.4 ช่อง `RSI OS` ยังไม่มีผลกับฝั่ง buy เลย และ `RSI OB` (70) ถูก
`noChaseHi` (62) ครอบไว้อยู่แล้ว = ปรับสองช่องนี้ยังไงก็แทบไม่มีอะไรเปลี่ยน

ตรงนี้ **น่าจะตั้งใจ** เพราะ v9.2/v9.3 ที่เอาไป backtest ใช้ตรรกะเลขตายตัวนี้
ถ้าแก้ ผลที่วัดไว้ 568 ไม้จะใช้อ้างอิงไม่ได้ทันที

v9.5 จึงทำเป็นสวิตช์ `ให้ RSI OB/OS มีผลจริง (แก้บั๊ก B2)` — **ปิดไว้เป็นค่าเริ่มต้น**
เปิดเมื่อไรก็ได้ตรรกะที่ถูก แต่ต้อง backtest ใหม่ ตารางไม่ได้โกหกอีกต่อไป

### F2. ข้อควรระวังที่เจอตอนเขียนส่วน ICT (เผื่อใครจะต่อยอด)

**วัด premium/discount จากขาที่พลิกอย่างเดียว = ไม่มีสัญญาณเลย**
FVG ที่เกิดจาก displacement จะอยู่ครึ่งบนของขานั้นเสมอโดยธรรมชาติ
ถ้าเอาขานั้นมาหาจุดกึ่งกลางแล้วบังคับ "Long ต้องอยู่ discount" จะไม่ผ่านสักไม้
ต้องวัดจากกรอบที่ครอบขาที่ลงมากวาดด้วย (v9.5 ใช้ `ictDrLook` = 40 แท่ง)

**อย่าเก็บ id ของ drawing ไว้ใน array ถ้าไม่ได้จำกัดจำนวน** — บั๊ก C2 เดิม
v9.5 เลยวาดกล่อง/เส้นแบบทิ้งเลย ไม่เก็บ id ปล่อยให้ `max_boxes_count`
กับ `max_lines_count` จัดการลบเก่าเอง ไม่มี id ค้างให้เรียกซ้ำ

**`low[i]` ที่ `i` เป็นตัวแปรลูป ต้องตั้ง `max_bars_back`** ไม่งั้นเจอ
"requested historical offset beyond the buffer's limit" เป็นครั้งคราวบนบางกราฟ
v9.5 ตั้ง `max_bars_back=500` ไว้ที่บรรทัด `indicator()`
