# v9 (fixed) — v9 ต้นฉบับ แก้เฉพาะบั๊ก

ไฟล์: [`src/XAUUSD_SMC_Pro_v9_FIXED.pine`](../src/XAUUSD_SMC_Pro_v9_FIXED.pine)
โค้ดสำหรับคัดลอก: [`CODE_v9_FIXED.md`](CODE_v9_FIXED.md)

ทำจาก `XAUUSD_SMC_Pro_v9.pine` ต้นฉบับโดยตรง **ไม่ยึดตาม v9.1 / v9.2 / v9.3 /
v9.4 / v9.5 / v10 ที่ทำไว้ก่อนหน้า** และไม่มีอะไรจากไฟล์เหล่านั้นปนเข้ามา

## กติกาที่ใช้ตัดสินว่าอะไรคือ "บั๊ก"

แก้เฉพาะจุดที่ **โค้ดทำไม่ตรงกับที่ตัวมันเองบอกว่าจะทำ** หรือ **ให้ตัวเลขที่ผิด**

- ไม่เพิ่ม input สักช่อง (ยังมี 40 ช่องเท่าเดิม)
- ไม่เพิ่มแถวในตาราง (ยังเป็น 10 แถวเดิม)
- ไม่เพิ่มฟิลเตอร์ ไม่เพิ่มเงื่อนไข ไม่เพิ่มระบบสัญญาณ
- ไม่แตะสูตร TP/SL ไม่แตะการให้คะแนน ไม่แตะเงื่อนไขเข้าไม้

ค่า default เปลี่ยนแค่ **ช่องเดียว** และขยายช่วงที่เลือกได้ **ช่องเดียว** — ทั้งสอง
เป็นส่วนหนึ่งของการแก้บั๊ก อธิบายไว้ในตารางข้างล่าง

โค้ดโตจาก 419 เป็น 526 บรรทัด ส่วนที่เพิ่มเกือบทั้งหมดคือคอมเมนต์อธิบายว่า
บรรทัดนั้นเดิมผิดยังไง ค้นคำว่า `FIX` ในไฟล์เพื่อกระโดดไปดูทีละจุด

## 11 จุดที่แก้

### FIX 1 — MTF repaint

คอมเมนต์เดิมเขียนว่า `no repaint (lookahead_off ...)` แต่ `lookahead_off` แปลว่า
"ไม่แอบดูอนาคต" ไม่ได้แปลว่า "ใช้ค่าที่ปิดแล้ว" ค่าที่ได้คือแท่ง HTF ที่กำลังก่อตัว
บนกราฟ H1 ค่า `bias_d1` จึงเปลี่ยนไปมาได้ทั้งวัน และประวัติไม่เหมือนเดิมเมื่อรีเฟรช

```pine
// เดิม
request.security(..., [ta.ema(close, emaFast), ta.ema(close, emaSlow)], lookahead=barmerge.lookahead_off)
// แก้เป็นสูตรที่ไม่ repaint จริง
request.security(..., [ta.ema(close, emaFast)[1], ta.ema(close, emaSlow)[1]], gaps=barmerge.gaps_off, lookahead=barmerge.lookahead_on)
```

### FIX 2 — ขอ TF ที่ต่ำกว่ากราฟ

บนกราฟ H1 การขอ M15/M30 ได้แค่ค่าสุดท้ายของ LTF ในแท่งนั้น ย้อนหลังกับ realtime
ไม่ตรงกัน ตอนนี้ตัดออกอัตโนมัติและแสดง `n/a` ในตาราง (ใช้ช่องเดิม ไม่เพิ่มแถว)

ผลพลอยได้ที่สำคัญ: `allBull`/`allBear` เดิมต้องการให้ครบทั้ง 5 TF **รวม M15/M30
ที่เชื่อไม่ได้** เมื่อเปิด `Realtime ต้อง MTF aligned` สัญญาณ realtime จึงแทบไม่มีทาง
เกิดเลย ตอนนี้นับเฉพาะ TF ที่ใช้ได้จริง

เกณฑ์ `ALIGN` ในตารางก็เดิมใช้ `mtfSum >= 3` ซึ่งสมมติว่ามี 5 TF เสมอ — ผิดทันที
เมื่อบาง TF ถูกตัด แก้ให้คิดตามจำนวน TF ที่เหลือจริง

### FIX 3 — default "ยืนยันด้วย TF" (ค่า default ที่เปลี่ยน)

`H1` → `H4`

ถ้าเปิดกราฟ H1 แล้วตั้งยืนยันด้วย H1 ค่า `confirmBias` จะเท่ากับ `ema21 > ema50`
ของกราฟเองเป๊ะ ๆ ผลคือ `mtfBuyOK` เท่ากับ `trendUp` — ฟิลเตอร์ MTF ไม่ได้กรอง
อะไรเพิ่มเลย แถมใน `buyScore` แต้ม `trendUp` กับเงื่อนไข MTF กลายเป็นเรื่องเดียวกัน
= **นับคะแนนซ้ำ**

นอกจากเปลี่ยน default แล้ว ถ้าผู้ใช้ยังเลือก TF ที่ไม่สูงกว่ากราฟ โค้ดจะใช้เทรนด์
ของกราฟตรง ๆ ไปเลย ไม่แกล้งทำเป็นว่ามาจาก TF อื่น

### FIX 4 — RSI OB/OS เป็นค่าตาย

```pine
rsiOK_buy = rsiVal > 35 and rsiVal < rsiOB and rsiVal < noChaseHi   // rsiOB=70, noChaseHi=62
```

`noChaseHi` (62) น้อยกว่า `rsiOB` (70) เสมอ เงื่อนไข `rsiVal < rsiOB` จึงไม่มีผลใด ๆ
และเลข `35` / `65` เป็น hardcode ที่ไม่ผูกกับช่อง `RSI OS` เลย → ปรับสองช่องนั้น
ยังไงก็ไม่มีอะไรเปลี่ยน

```pine
rsiOK_buy  = rsiVal > rsiOS and rsiVal < math.min(rsiOB, noChaseHi)
rsiOK_sell = rsiVal < rsiOB and rsiVal > math.max(rsiOS, noChaseLo)
```

> ที่ค่า default (OS 30 / OB 70 / noChase 38-62) ผลลัพธ์กว้างกว่าเดิมนิดเดียว
> เพราะขอบล่างขยับจาก 35 เป็น 30 ถ้าอยากได้พฤติกรรมเดิมเป๊ะให้ตั้ง `RSI OS` = 35

### FIX 5 — Volume filter พังถ้าฟีดไม่มี volume

ฟีด XAUUSD หลายเจ้า `volume` เป็น `na` ทำให้ `volume > avgVol * 0.7` เป็น false
ตลอด = เสียคะแนนฟรี 1 แต้มทุกแท่ง สัญญาณแทบไม่ผ่าน `minScore`
เพิ่ม `na(volume) or na(avgVol)` เป็นทางผ่าน

### FIX 6 — Min Score เลือกได้ไม่ครบช่วง (ช่วงที่ขยาย)

`maxval` เดิมคือ 5 แต่คะแนนเต็มจริงคือ 7 → ตั้งเกิน 5 ไม่ได้ทั้งที่ระบบทำได้
เปลี่ยนเป็น `maxval=7` **ค่า default ยังเป็น 4 เท่าเดิม**

### FIX 7 — บัฟเฟอร์ swing บวกผิดจังหวะ

```pine
// เดิม: เช็คเพดานก่อน แล้วค่อยบวกบัฟเฟอร์ แล้ว cap อีกที
buyUseSwing = ... buySwingDist <= maxSLusd
buySLdist   = buyUseSwing ? math.min(buySwingDist + atrVal * 0.1, maxSLusd) : slDistBase
```

ไม้ที่ swing อยู่ใกล้เพดานพอดีจะจบที่เพดานเป๊ะ ๆ โดยไม่ได้ตั้งใจ (บัฟเฟอร์หายไป
เฉย ๆ) แก้ให้รวมบัฟเฟอร์เข้าไปก่อนแล้วค่อยตัดสินว่าจะใช้ swing หรือไม่

### FIX 8 — `buyQualOK` เป็นจริงเสมอ

`buySLdist > 0` — ATR มากกว่า 0 ตลอด เงื่อนไขนี้ไม่เคยกรองอะไรเลย
เติม `not na(atrVal)` เข้าไปให้มันกันแท่งแรก ๆ ของกราฟได้จริง

### FIX 9 — เลข point ผิดกับโบรกที่ทองมี 3 ทศนิยม

```pine
buyTP1Pts = math.round(buySLdist * rr1 / 0.01)   // 0.01 ตายตัว
```

OANDA แสดงทองเป็น 4,586.**970** = 3 ทศนิยม → 1 point เท่ากับ 0.001

```
SL 12 $/oz  →  ป้ายบอก "1200 point"  →  ที่ถูกคือ 12000   (ผิด 10 เท่า)
```

แก้เป็น `syminfo.mintick` ซึ่งเป็นขนาดขั้นราคาจริงของสัญลักษณ์นั้น
**เลขราคา (เข้า / TP / SL) ถูกอยู่แล้ว ผิดเฉพาะเลข point ในวงเล็บ**

### FIX 10 — โหมด Limit นับผลทั้งที่ออเดอร์อาจไม่เคยติด

ป้ายบอกว่า "วาง Buy Limit ต่ำกว่าราคาปิด 0.4 × ATR" แต่โค้ดเริ่มเช็ค TP2/SL ทันที
ตั้งแต่แท่งที่เกิดสัญญาณ โดยไม่เคยเช็คว่าราคาย่อลงมาแตะราคาเข้าหรือยัง

ตัวอย่างที่พังชัด ๆ: entry อยู่ต่ำกว่า close 6.8 และ TP2 อยู่เหนือ close 14.8
ถ้าราคาวิ่งขึ้นอย่างเดียวโดยไม่ย่อ → เส้นบนกราฟบอกว่าไม้นี้ TP2 แล้ว ทั้งที่ใน
บัญชีจริงออเดอร์ไม่เคยติดเลย

เพิ่มสถานะ `pending` ใน `TradeViz` (ไม่ใช่ input ใหม่) — ต้องแตะราคาเข้าก่อน
ถึงเริ่มนับผล ไม้ที่ไม่เคยติดจะค้าง pending และเส้นยืดต่อไปเรื่อย ๆ ซึ่งมองแล้ว
รู้ทันทีว่าออเดอร์นี้ไม่เคยเข้า

### FIX 11 — array โตไม่จำกัด

- ไม้ 1 ไม้ = 4 เส้น ประมาณ 125 ไม้ก็ชน `max_lines_count` (500) TradingView
  จะลบเส้นเก่าทิ้งเอง แต่ `trades` ยังถือ id เดิม → `line.set_x2` ไม่มีผล เส้นค้าง
- `bullBoxes` / `bearBoxes` เหมือนกัน โดยเฉพาะเมื่อปิด `ลบ FVG ที่ถูกเติมแล้ว`
  (ไม่มีอะไรลบเลย) แล้ว `box.get_bottom()` ไปอ่านกล่องที่ถูกลบไปแล้ว

จำกัดไว้ 60 ไม้ / 60 กล่องต่อฝั่ง แล้วลบเส้นกับกล่องพร้อมกับเอาออกจาก array
(ตัวเลขฝังในโค้ด ไม่ได้ทำเป็น input ตามที่ตกลงว่าไม่เพิ่มช่อง)

## สิ่งที่ "ไม่ได้แก้" โดยตั้งใจ

สี่ข้อนี้เป็นการออกแบบของ v9 ไม่ใช่โค้ดเขียนผิด การแก้ต้องเพิ่ม input หรือ
เปลี่ยนพฤติกรรมการเทรด ซึ่งอยู่นอกขอบเขต "แค่แก้บั๊ก"

### 1. เพดาน SL ยังบีบ SL แล้วเข้าไม้อยู่ดี — ข้อนี้กระทบเงินมากที่สุด

```pine
slDistBase = math.min(atrVal * slAtrMult, maxSLusd)
```

ช่องนี้ชื่อ "SL สูงสุด ($)" และมันก็ทำตามชื่อเป๊ะ ๆ คือ cap ให้ไม่เกิน — จึงไม่ใช่บั๊ก
แต่ผลข้างเคียงคือ **ไม้ที่ระบบเองประเมินว่าต้องใช้ SL กว้างกว่าเพดาน จะถูกหั่น SL
ให้แคบแล้วเข้าไม้อยู่ดี** ไม่ได้ข้ามไป

เห็นได้จากกราฟจริง ตอน ATR(14) = 17.09 บน H1

```
ระบบอยากได้ SL = 17.09 × 1.2 = 20.51
เพดาน maxSLusd = 12  →  หั่นเหลือ 12  =  0.70 ATR เท่านั้น
```

นี่คือเหตุผลที่ป้ายทุกใบบนกราฟมี SL เท่ากันเป๊ะที่ $12 — มันชนเพดานทุกไม้

**ถ้าจะจัดการเอง**: เพิ่ม `SL สูงสุด ($)` ให้พอกับ ATR ของ TF ที่เล่น
สำหรับทอง H1 ยุคนี้ประมาณ **20–25** ไม่ใช่ 12 หรือลด `SL = ATR ×` ลงถ้าอยาก
ให้ SL แคบจริง ๆ แต่ต้องรู้ตัวว่ากำลังเลือกความแคบ ไม่ใช่โดนหั่นแบบไม่รู้ตัว

### 2. FVG ยังเป็นแค่กราฟิก

`bullFVG` / `bearFVG` ไม่ปรากฏใน `buyScore`, `baseBuy` หรือที่ไหนอีกเลย
ทั้งก้อนอยู่ใน `if showFVG` → ปิดปุ่มแสดงผลก็หายไปทั้งหมด ซึ่งไม่เป็นไรเพราะ
มันไม่ได้ถูกใช้ตัดสินใจอยู่แล้ว การทำให้ FVG มีผลกับคะแนน = เพิ่มฟีเจอร์

### 3. Min Score 4 ผ่านได้โดยไม่มี BOS/CHoCH

`trendUp + rsiOK + trigger + volOK` = 4 แต้มพอดี ครบตาม default แปลว่า
BOS / CHoCH / marketBias ไม่จำเป็นต้องเกิดเลย ระบบก็ยิงสัญญาณ

ตอนนี้ตั้ง `Min Score` เป็น **5 ขึ้นไป** ได้แล้ว (FIX 6) ซึ่งบังคับให้ต้องมีโครงสร้าง
SMC อย่างน้อยหนึ่งอย่าง — เป็นการตั้งค่า ไม่ต้องแก้โค้ด

### 4. เลข `$` ยังคิดที่ 100 oz ต่อ lot

`buySLusd = buySLdist * lotSize * 100` — เลข 100 ฝังไว้ ถูกกับบัญชีมาตรฐาน
แต่บัญชี micro (10 oz) หรือ cent (1 oz) จะได้ตัวเลขเกินจริง 10–100 เท่า
การแก้ต้องเพิ่มช่อง "1 lot = กี่ oz" ซึ่งเป็นการเพิ่ม input

**ถ้าใช้บัญชี micro/cent**: ตัวเลข `$` ในป้ายให้หารด้วย 10 หรือ 100 เอาเอง
ส่วนเลขราคาและ point ถูกทุกบัญชี
